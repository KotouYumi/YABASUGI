# YABASUGI v1.00 — CMS分離版

## 公開対象
このフォルダのファイルをGitHubリポジトリのルートに配置し、従来どおりVercelで公開する。ビルドは不要。`index.html`、`firebase-config.js`、`brand.png`、`bingo-illustration.jpeg`、`audio/` が動作に必要。

**公開前にFirebase Realtime Databaseの現行データとSecurity Rulesをバックアップすること。** 本版は既存のFirebaseプロジェクトとパスを維持するため、起動時にデータを自動移行・初期化・書き換えない。

旧リポジトリの次のファイルは削除する（上書きアップロードだけでは残存する）。
- `yabasugi-site-data.json`
- `product-sources.json`
- `merch-images.json`
- `import_merch_images.py`
- 旧 `merch-images/` があれば削除（使用中の画像は先に編集画面で保存し直す）
- `database.rules.json` と `firebase.json` は今回のVercel公開物には含めない。旧ルールファイルは適用しない。Firebase側設定は別工程。

Git履歴に含まれる旧コンテンツは通常の削除コミットでは消えない。必要なら別途履歴整理・アクセス制限を検討する。

## 構造
- GitHub：アプリケーション、共通デザイン、固定ロゴ・抽選機イラスト・音源のみ。
- Firebase `/site/content`：記事、バナー、商品、商品カテゴリ、公開設定。既存形式を維持し、空の配列がFirebaseで省略されても読み込み可能。編集操作時のみ保存。商品・記事・バナーを含むJSONのバックアップと明示的復元に対応。
- Firebase `/site/bingo`：抽選履歴、電源状態、リセット識別子。記事保存の対象外。
- Firebase `/site/bingoCards`：参加者の共有カード。端末のカード本体・穴あけ・ニックネームは引き続き端末内に保持する。
- コンテンツのローカルフォールバックと埋め込み初期データは廃止。Firebaseにデータがなければ空のサイトになる。管理者の追加操作によって登録する。

## 管理画面
グッズ販売管理で商品を登録し、サイト編集で記事内の任意位置に個別の商品を挿入する。連続する商品は2列・縦横比3:4で表示する。全商品一括表示は廃止したため、従来の自動一覧だけに依存していた記事は手動で商品参照を挿入し直す。未配置の装飾も表示しないため、必要なら記事内に配置指定を追加する。商品情報の変更は参照先に反映される。

データ管理からイベントモードを設定するとオフライン特典会以外の分類とトップバナーを隠す。これは画面上の表示制御であって、データへのアクセス制限ではない。

## Firebase別工程（未適用）
実際の管理者UID、認証設定、データ、Security Rulesを確認すること。旧ルールに全配列の存在を必須とする検証がある場合、空データの保存が拒否される。抽選履歴・カードの読み書き・トランザクション・リセットの権限も精査する必要がある。匿名認証とカードの所有者UID制御、非公開コンテンツをデータレベルで保護する設計は今版では導入していない。現在の公開データが読める権限を前提とする。管理者の権限はサーバー側ルールで制限すること。Firebaseの実設定を変えるまでは本番での全機能の動作を保証しない。
